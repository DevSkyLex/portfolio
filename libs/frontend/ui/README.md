# @vfortin/ui

## Purpose

In-house component catalogue of the Orbite design system (`scope:platform`, `layer:ui`). The list and the names follow the Spartan UI / shadcn catalogue, but nothing comes from Spartan: the behaviour relies on `@angular/cdk`, the look on Tailwind classes over the tokens of `@vfortin/design-tokens`, and the icons on `@ng-icons/lucide`.

Components may be unused by the site. `package.json` declares `"sideEffects": false` so that the build drops whatever the app does not import; Tailwind scans folders, not imports: the public `apps/web/src/styles.css` lists one `@source` per catalogue folder the public pages use (checked against the import graph by `npx nx run architecture:test`, D31), and the admin's `apps/web/src/admin.css` scans the whole catalogue. A component newly used by a public page needs its folder added there.

## Public entry points

| Entry point   | Consumers                                                                                                                                                                          |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `@vfortin/ui` | `contact-web-feature`, `contact-web-feature-admin`, `content-web-feature`, `content-web-feature-admin`, `content-web-ui`, `identity-web-feature`, `legal-web-feature`, `web-shell` |

The root is the supported visual catalogue surface. Private host tokens, render IDs, shared menu
implementation and overlay containers are not public import shortcuts. Consumers choose controls from
this entry instead of duplicating their interaction behavior in a feature.

## Provider scope

State that belongs to one control is provided by that control or its containing group. Overlay
references, DOM listeners and animation work are disposed with the owner. Application-wide toast,
scroll scheduling and ID services remain domain-agnostic; ID counters belong to an application
injector rather than the JavaScript module lifetime.

## Invariants

- The catalogue imports no business model, store, HTTP client or backend implementation.
- Controls use native semantics where possible, typed signal inputs/outputs and Angular form-control
  contracts; focus and keyboard behavior are part of the public API.
- Styling uses literal token-based Tailwind classes and the shared interactive/status scales.
- Server rendering and hydration must not reuse module-global identity across application instances.
- Overlay close and component destruction release listeners, views and scheduled work.

## Validation

Run `npx nx run-many -t lint typecheck test -p ui` and `npx nx run architecture:test`. Component tests
cover value-control, state, keyboard and ARIA contracts. Repeated application rendering and browser
hydration qualify IDs; browser tests qualify actual geometry, overlays, reduced motion and focus.
See [testing](../../../docs/workspace/testing.md) and decisions D26, D35, D37 and D43.

## Conventions

- Directive on the native element whenever possible (`button[uiBtn]`, `div[uiCard]`); a `ui-*` component only when it owns a template.
- Variants with `cva`, merged with the caller's `class` input through `cn` (tailwind-merge extended with the theme scale, radii, easings and animations); `data-slot="<name>"` on every host.
- Value controls implement the Signal Forms `FormValueControl<T>` / `FormCheckboxControl` contracts: bind them with `[formField]`.
- `ui-field` owns the error state: bind its `[error]` (the message to show, or `null`) and every catalogue control projected into it (`uiInput`, `uiTextarea`, `uiInputGroupInput`, `ui-select`, `ui-input-otp`, `ui-tags-input`, `ui-combobox`, `ui-autocomplete`, `ui-month-picker`, `ui-period-picker`) carries `aria-invalid="true"` while the message shows, so their `aria-invalid:` styles follow; the caller binds no `aria-invalid` itself and keeps its `aria-describedby` (`<id>-error` / `<id>-hint`). A control outside a field keeps its own binding. `size="sm"` gives the dense admin type: 13 px label, 12 px hint and error.
- Small controls (checkbox, radio, switch, OTP slot) take the 2 px `outline-accent/55` focus ring of links and sidebar entries; an invalid control keeps its danger border under it.
- Accessible default texts are `$localize` messages with `@@ui.<component>.<key>` ids, French source; each can be overridden by an input. A message only reaches `messages.xlf` once the app uses its component: run `extract-i18n` and translate it then.
- One declaration kind per file (D37): component, directive and service files keep their existing declaration contracts and related injection helpers (`linkDialogTitle`, `injectDialogContainer`, `openDialogPanel`). Public names remain imported from `@vfortin/ui`.
- Each catalogue entry is a coherent unit. Its primary matching component/directive may stay at the entry root; child units live in `components/<name>/`, `directives/<name>/` or `services/<concern>/`, with their templates and `testing/` alongside them.
- Related interfaces, aliases and const-enum models live in `models/<concept>/`. Flat `constants/` holds `*.variants.ts` (`cva` families and derived unions), `*.constants.ts` and `*.imports.ts` tuples. Tokens use `tokens/<concern>/`; pure functions use `utils/<helper>/`. Constants/options do not need a directory per value or file.
- `src/index.ts` re-exports each public file with one `export * from` line; inside the library, imports use `@internal/ui/lib/...`.
- Statuses use the `success`, `warning`, `danger` and `info` families (`-ink` for text, `on-fill` on a fill); `accent` only marks focus, selection and the brand accent (D37); states use `surface-hover` and `surface-selected` (D41). Text starts on the left; only inherently centred parts (icon buttons, OTP slots, calendar cells, spinner) and the empty state (`uiEmpty`, the owner's exception) centre their content.
- Dialog and alert-dialog panels pad with `--dialog-inset` (`--spacing(6)`, 24 px at every width, the same for every admin dialog), which the `bar` header and footer cancel to reach the edges: a caller resizing the padding of a panel holding a bar sets the variable (`[--dialog-inset:0px]` for an edge-to-edge list), not `p-*`. Both bars keep the panel surface behind a hairline and share one height (`min-h-13`); the close button centres on a header bar. Keyboard hints go first in the footer bar and the actions in a trailing `ml-auto` group. Panels have two widths, the `size` option of `DialogService.open` and `AlertDialogService.open`: `sm` 420 px (a question or one or two fields; the alert-dialog default), `md` 512 px (a form or richer content; the dialog default) and `lg` 576 px (`ConfirmDialogService`, whose footer holds a key hint and two long labels).
- Radii follow the size scale of D43 (`rounded-2xs` 2 px to `rounded-xl` 12 px, no other radius exists): `xs` for kbd, badges, checkboxes and chips, `sm` for h-7/h-8 controls, options, sidebar entries and tab triggers, `md` for fields and buttons from h-9 to h-11, `lg` for menus, lists, popovers and toolbars, `xl` for cards, dialogs, sheets and toasts. An element hugging a rounded container with a gap of 8 px or less takes the container radius minus the gap (edge to edge, border included): menu panels pad `p-[3px]` inside their border so `lg` = `sm` + 4; a generous padding (16 px or more) lets each element keep its own step. A size override below h-9 takes its radius along (`size="xs"` on buttons, `size="icon-xs"` / `size="icon-sm"` for 28 / 32 px square icon buttons, or `h-8 rounded-sm`).
- Overlay templates (`ng-template` with `uiPopoverContent`, `uiSheetContent`, `uiDialogContent`, `uiAlertDialogContent`, `uiHoverCardContent`) take their panel classes through a bound `[class]="'…'"`: Angular never passes a static `class` attribute of an `<ng-template>` to an input.
- Specs live in each folder's `testing/`.

## Data table

Empty states (D36 empty state revision) are one composition, `uiEmpty` with `uiEmptyHeader`,
`uiEmptyMedia variant="icon"` (a 36 px `md` tile on the raised surface holding a 16 px lucide icon),
`uiEmptyTitle` (14 px medium), `uiEmptyDescription` (13 px muted, 60ch at most) and `uiEmptyContent`
(the actions, the primary one first, `uiBtn size="xs"`), always centred horizontally (`items-center`,
`text-center`, the description `mx-auto`): the owner's exception to the left-aligned text of the
admin, allowed for these files only by `design.spec.ts`. Its `layout` follows its position: `fill` when
nothing follows it in its page column (it takes the remaining height, at least 18rem, with the page
gutters, its content centred in the free room, `justify-center`); `inline`, the default, when something
follows it (pagination, another section, more options: 32 px of block padding, no stretching, no
gutter, centred horizontally only); `panel` when it is the only content of a bounded pane, sheet or
media frame (`h-full`, 16 px inset, centred in the box, `min-h-0` so it never makes the box scroll). `ui-data-table` takes the rule
through `emptyLayout` (`fill` or `inline`): its empty and no-result states sit below the heading row,
not in a spanning cell, a `fill` table grows into the rest of its flex column, and an
`ng-template[uiDataTableEmpty]` receives the layout as `let-layout`.

`ui-data-table` filters, sorts and paginates in memory. Its view state is one serialisable
`DataTableState` model (`search`, `facets`, `sort`, `page`, `pageSize`, `hidden`), bound with
`[(state)]` so that a page can mirror it in its URL; a search, facet or page-size change goes back to
the first page and an out-of-range page is clamped. Facets (`DataTableFacet`: id, label, value accessor,
options or options derived from the data) combine OR within a facet and AND across facets, with counts
taken within the search and the other facets. `searchPredicate` replaces the default search (every word
in the searchable cell values, accents ignored). Sorting is stable, collated with `LOCALE_ID`, keeps
empty values last and adds a key on Shift+click. `activatable` rows emit `rowActivated` on a click or on
Enter, never from the links, buttons, inputs and menus inside them. `loading` renders skeleton rows,
`ng-template[uiDataTableEmpty]` (context `let-layout`) replaces the no-data state, and the no-result
state (`noResults`, `noResultsHint`) offers « Réinitialiser les filtres »; both are `uiEmpty` blocks
under the heading row whose height follows `emptyLayout`. Without rows a table without resizable columns keeps the column widths last measured,
written to a `colgroup` under the fixed layout, so that no column class (a `w-full max-w-0` title
included) moves the columns. Checked
facet values show once, as removable chips in the toolbar (the facet button carries no count); the
column menu hides below 640 px. The page size is a `ui-select` (h-8, `rounded-sm`). `selectable` rows
carry catalogue checkboxes (the header one selects the visible page, indeterminate when partly
checked); the `selection` model survives sorting and paging, drops the rows a search or facet hides and
takes the fresh row objects after a reload; pair it with `ui-selection-bar` for bulk actions.
`resizableColumns` switches to the fixed layout with a `colgroup` that holds the model, never a
measure (D36 column resizing revision): the selection column (40 px framed, 52 px flush) and every
column with a `width` are fixed in pixels (the stored width, else the `width`), and the first column
without one (give exactly one) fills the room left, down to its `minWidth` (200 px by default), below
which the table takes the sum as its minimum width and the frame scrolls sideways (with
`stickyHeader`, on both axes within the viewport, the heading sticking to its top). Every fixed column
that does not opt out (`resizable: false`) gets a focusable separator on the edge facing the fill
column (its start edge after it, its end edge before it), so that the dragged edge follows the pointer
while the fill column absorbs the change; the fill column has none. Drag (no width changes on press,
one update per animation frame, a dashed full-height guide, the `col-resize` cursor on the document,
Escape cancels, stored on release), arrows by 16 px (64 with Shift), Home and End to `minWidth` /
`maxWidth`, double click or Enter to fit the widest heading or visible cell, Shift with either to
restore the `width`, Escape to leave the handle. With a `columnWidthsKey` the widths are kept per
viewer in `localStorage`, only for existing fixed resizable columns and within their bounds. Texts
default to French `@@ui.data-table.*` messages and are overridden through `labels`.

## Keyboard shortcuts

A trigger with a shortcut shows its caps in its tooltip and names it for assistive technology, both
from `ModifierKeyService`, which writes `Mod` as the platform modifier:

```html
<button
  uiToggle
  aria-label="Liste à puces"
  uiTooltip="Liste à puces"
  [tooltipShortcut]="modifier.caps(['Mod', 'Maj', '8'])"
  [attr.aria-keyshortcuts]="modifier.ariaKeys(['Mod', 'Maj', '8'])"
></button>
```
