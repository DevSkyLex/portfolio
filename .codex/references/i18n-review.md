# Localization review

A read-only reference for a bounded review of the French source messages and their English
translations.

- Locales: source `fr` at `/` (`sourceLocale` with an empty `subPath`), `en` at `/en/`
  (`apps/web/project.json`). The production build compiles both with `i18nMissingTranslation: "error"`;
  the development server serves French only.
- Catalogs: `apps/web/src/locale/messages.xlf` is generated by `npx nx run web:extract-i18n` and never
  hand-edited; `apps/web/src/locale/messages.en.xlf` holds the English targets. Both are excluded from
  Prettier (`.prettierignore`). A reviewer never regenerates them: ask the parent for the extraction diff
  and the `npx nx build web` result.
- Ids are explicit and dotted (`@@contact.error.email`, `@@route.home`, `@@error.404.title`,
  `@@ui.dialog.close`). Report implicit ids, duplicates with different sources, French left in a target,
  English left in a source, missing or empty targets, changed placeholders and broken ICU plurals
  (`@@contact.failed.one` / `.many`).
- Catalogue defaults (`@@ui.*`) enter the catalog only once the app uses the component.
- The admin area is French only and not translated (D18); plain strings there are expected.
- Projects, journey and profile copy come from the content service through
  `apps/web/content-snapshot/{fr,en}.json`, not from the XLF files.
- French copy addresses the reader with "vous"; errors say what broke and how to fix it; terminology
  stays consistent (projets, parcours, à propos, contact). English targets keep the meaning; long labels
  are listed for a browser check at 390 px on `/en/`.

Return file/line or unit id, consequence, evidence, minimal correction and the unverified cases.
