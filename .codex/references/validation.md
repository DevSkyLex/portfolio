# Select validation by the changed boundary

The workspace exposes npm scripts and Nx targets. Run the narrowest useful check first; widen only when the change crosses boundaries. A passed command proves its boundary, not the whole application. CI separates format, architecture and affected lint/typecheck/build from coverage tests; e2e runs on main and on pull requests when affected (`.github/workflows/ci.yml`).

| Change                                                                       | Check                                                                                                             | Evidence and limit                                                                                                                    |
| ---------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| Agent tooling (`.codex/`, the Claude Code folder, `.githooks/`, `.mcp.json`) | the commands of [maintenance](../maintenance.md)                                                                  | Validators, parity, links, hook behaviour; no application build                                                                       |
| Documentation only                                                           | scoped `npx prettier --check <files>` and link review                                                             | No executable or configuration change                                                                                                 |
| One library                                                                  | `npx nx lint <project>`, `npx nx typecheck <project>`, `npx nx test <project>` (`-- <filter>` to narrow)          | The project and its own specs                                                                                                         |
| Imports, tags, new project or rule                                           | `npx nx affected -t lint`, `npx nx run architecture:test`                                                         | `@nx/enforce-module-boundaries`, the file-cycle architecture gate, the rejected-import proof                                          |
| Templates, routes, providers, public copy                                    | `npx nx build web`                                                                                                | Strict templates, prerender of every public route, FR/EN localization (missing translation fails), 700 kB warning / 1 MB error budget |
| Public copy or message ids                                                   | `npx nx run web:extract-i18n`, English targets, then `npx nx build web`                                           | Catalog parity; no proof of wording or layout ([i18n review](i18n-review.md))                                                         |
| Backend context                                                              | `npx nx run-many -t lint typecheck test -p <ctx>-*` projects, `npx nx build <ctx>-service`                        | Domain, use cases, repositories on PGlite, composition over HTTP                                                                      |
| Schema                                                                       | `npx drizzle-kit generate --config apps/<ctx>-service/drizzle.config.ts`, `npx nx run <ctx>-service:db-migrate`   | Generated SQL reviewed, applied to the local PGlite database                                                                          |
| Contracts                                                                    | `npx nx test <ctx>-contracts` and the consumers' tests                                                            | Fixture parity; snapshot breaks surface at `npx nx build web`                                                                         |
| Browser behaviour                                                            | `npx nx build web`, then `npx nx e2e web-e2e` ([e2e](e2e.md))                                                     | Built-site public acceptance; isolated `web-e2e:e2e-stack` for authenticated service journeys                                         |
| Docker, Nginx, Ansible                                                       | `docker compose -f docker/compose.dev.yml config`, `sh -n <script>`, `ansible-playbook <playbook> --syntax-check` | Static only; never against production                                                                                                 |
| Formatting                                                                   | `npx nx format:check` (whole repository), `npx prettier --write <files>` (bounded)                                | Prettier with `.prettierrc`; the format hook already formats each edited file                                                         |
| Before finishing a change                                                    | `npx nx affected -t lint typecheck test build` and `npx nx run architecture:test`                                 | Required local gate; CI runs corresponding checks in separate jobs                                                                    |

On a repository without commits yet, `affected` has no base: use `npx nx run-many -t <targets>` for the
touched projects instead.

## Reading results

Report failed or skipped checks with their reason; distinguish existing failures from regressions; use
the smallest rerun that validates a correction. Do not keep widening once the relevant risks are covered.
