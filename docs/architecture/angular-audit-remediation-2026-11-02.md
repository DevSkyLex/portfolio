# Angular audit remediation

Implementation date: 2026-11-02. This report follows the
[Dentalstock comparison audit](angular-dentalstock-audit-2026-11-02.md). It records the corrections to
F01–F13 and the secondary observations; the original report remains the historical baseline.

The application keeps its Nx context/layer boundaries, private source aliases, shared API contracts,
public prerendering and French-only CSR administration. Dentalstock's ownership, concurrency,
presentation and validation conventions apply inside those boundaries. No catch-all project or
parallel architecture was introduced. [D32, D38 and D39](decisions.md) and the
[boundary rules](boundaries.md) describe the maintained contracts.

[Feature tests][identity-feature-tests] use real back/return controls and delayed auth answers; [data-access tests][identity-tests] cover ordered cleanup.                                                                                                          |

[Login tests][identity-feature-tests] assert malformed email cannot submit even with native validation disabled.                                                                                                                                                                                                                                                          |
| Preview/Nginx route parity     | The [built-site server][preview] handles French-only admin redirects, admin `no-store`/`noindex`, public/hashed cache policy, HEAD, localized true 404s and malformed/traversing/escaping paths. [HTTP tests][preview-tests] include symlink containment. It models application routing; TLS, rate limiting, proxy trust, compression and maintenance remain Nginx/Compose concerns.                                                                                  |
| Theme listener cleanup         | The [theme service][theme] retains its media handler and disposes it through `DestroyRef`; [theme tests][theme-tests] cover teardown.                                                                                                                                                                                                                                                                                                                                 |
| Strict and explicit typing     | Production frontend lint now checks explicit return/module boundaries, type imports, accessibility, unsafe operations, assertions, exhaustiveness, template interpolation, readonly fields and unbound methods. Angular nullish/optional extended diagnostics are errors. Explicit `inject<T>()` calls and project-private aliases remain the convention. The global gate checks production and test semantics; these rules do not substitute for runtime acceptance. |
| Catalogue SSR identifiers      | [Render IDs][render-id] are injector-scoped instead of module-global. [Repeated-render and hydration tests][render-id-tests] use real server rendering and verify existing hydrated DOM nodes, disclosure/select ARIA relationships, interactions and explicit IDs. This qualifies representative controls; it does not assert exhaustive browser hydration coverage of the whole catalogue.                                                                          |
| Decorative renderer failure    | A rejected planet chunk retains a stationary token-based fallback. Destroyed or superseded owners ignore late resolutions/rejections. [Import-failure tests][planet-tests] cover these cases.                                                                                                                                                                                                                                                                         |
| Keyboard startup timing        | The public skip link is explicitly keyboard-focusable; [navigation E2E][navigation-e2e] waits for application readiness and exercises normal Tab/Enter across the configured browsers.                                                                                                                                                                                                                                                                                |

## AI tooling cleanup

Only Claude, Codex and their useful shared resources remain: `AGENTS.md`, `CLAUDE.md`, `.agents/`,
`.mcp.json` and project documentation. OpenCode configuration and Copilot's duplicate agents, prompts
and skills were removed; the other client-specific trees are absent. GitHub workflows and general
editor configuration remain. `npm run ai:configure` explicitly selects Claude and Codex for future Nx
updates. Maintained client documentation and the adapter test now refer to retained resources;
Claude's plugin patch version is `0.1.2`. See the [AI tooling audit](../workspace/ai-tooling-audit.md).
The seven root diagnostic logs produced by this implementation were removed.

localhost sockets, create a symlink fixture or use browser/compiler temporary directories run outside
the filesystem sandbox. That changes the runner permissions, not the application behavior.

The disposable stack mounts committed public development examples directly. It neither prepares nor
reads private development secrets, resets an existing administrator, nor uses the developer's volumes.
The runner validates ownership before startup and removes only its generated project and volumes in
its finalizer. [Browser acceptance documentation](../../apps/web-e2e/README.md) describes the commands,
ports, isolation and scope. No commit, deployment or production change is part of this remediation.
